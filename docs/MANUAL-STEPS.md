## 0) ربط MsgPlus — الكود جاهز، والقيم وصلت (إعداد Render ينتظرك)

رموز التحقق **عبر MsgPlus SMS فقط** (لا واتساب/Green API ولا Firebase SMS). المحوّل `lib/messaging.ts` يتبع وثائق MsgPlus API v1: `POST https://sms.msgplus.tech/api/v1/send` بترويسات `Authorization: Bearer`, `X-Timestamp` (ثوانٍ، لكل طلب), `Accept`، وجسم `sender_id` + `template_id` + `numbers` + `vars`. الإرسال **بقالب معتمد**: يُرسل الرمز وحده داخل متغير القالب.

### متغيرات Render (الخدمة `al-euro`) — أربعة فقط
| المتغير | القيمة |
|---|---|
| `MSGPLUS_API_KEY` | **مفتاح الـ API (سر، يوضع في Render فقط)** — يُقبل بدون كلمة Bearer أو معها |
| `MSGPLUS_SENDER_ID` | `157` |
| `MSGPLUS_TEMPLATE_ID` | `1` |
| `MSGPLUS_OTP_VAR_NAME` | `P1` |

الباقي يُشتق تلقائياً (الرابط، `Authorization: Bearer`، `X-Timestamp`، `Accept`، فحص `success=true`). المتغيرات العامة (`MSGPLUS_API_URL`، `MSGPLUS_BODY_TEMPLATE`، …) اختيارية وتتغلّب على المشتق عند ضبطها. **تحقّق من نص القالب رقم 1** في لوحة MsgPlus: يجب أن يحوي المتغير `[[P1]]` فقط ويذكر «10 دقائق»، مثل:
`EURO CARS: رمز التحقق [[P1]] صالح 10 دقائق. لا تشاركه.`
(قالب بمتغيرات أخرى يردّ 422 ولا يُرسَل شيء.) إن كانت قيمة غير صالحة (رقم غير صحيح، مفتاح قصير …) يعدّ الخادم التكامل «غير مُعدّ» ولا يرسل شيئاً.

ثم: `REGISTRATION_OTP_ENABLED` يبقى `false`، و`OTP_DAILY_CAP` اختياري (الافتراضي 500).

### ترتيب النشر الآمن
1. أضف المتغيرات الأربعة في Render (الكود الحالي المنشور لا يقرؤها، فلا أثر).
2. ارفع `al-euro` فقط إلى `main` (لا ترفع `al-euro-referrals` ولا تطبيق Flutter الآن).
3. بعد اكتمال النشر: «نسيت كلمة المرور» من حسابك برقمك أنت، مرة واحدة. المتوقع: وصول الرمز خلال دقيقة، صالح 10 دقائق، 5 محاولات، استخدام واحد.
4. رد MsgPlus 202 = «في الطابور» وليس «وصلت»؛ التتبع عبر `GET /sms/{id}/status`. عند رصيد غير كافٍ يسجّل الخادم الرمز `INSUFFICIENT_BALANCE` فقط (بلا رقم ولا مفتاح).

### أسئلة لدعم MsgPlus (الإجابات تأتي من MsgPlus وحدهم؛ لا توجد في الوثائق التي اطّلعتُ عليها)
| السؤال | ما هو مثبت لدينا | ما ينقص |
|---|---|---|
| مهلة تفاوت `X-Timestamp` المقبولة؟ | نرسل الوقت الحالي (ثوانٍ) في كل طلب وعمل الإرسال الحقيقي | الحد الأقصى المسموح لانحراف ساعة الخادم |
| حدود المعدل (طلبات/ثانية، رسائل/رقم)؟ | لا نرسل أكثر من رمز لكل حساب كل دقيقة و5 كل ساعة، وسقف يومي `OTP_DAILY_CAP` | حدود المزوّد نفسه وكيف يرد عند تجاوزها (429؟) |
| بيئة اختبار (sandbox)؟ | اختبار حقيقي واحد نجح: وصل الرمز خلال أقل من دقيقة | هل توجد أرقام/وضع تجريبي بلا رصيد |
| قيود قوالب رموز التحقق؟ | القالب 1 يحوي `[[P1]]` فقط ويعمل | هل يجوز تعدد القوالب/تغيير النص، ومدة اعتماد قالب جديد |
| تغطية الأرقام السورية (سيريتل/MTN) وتكلفة الرسالة؟ | وصلت رسالة إلى رقم المستخدم في اختبار واحد | التغطية الكاملة للمشغّلين، التكلفة، ونسبة التسليم |
| تتبّع التسليم؟ | الرد 202 = «في الطابور» فقط | هل يوجد Webhook لحالة التسليم أو نكتفي بـ `GET /sms/{id}/status` |
| رصيد منخفض؟ | عند `INSUFFICIENT_BALANCE` يسجّل الخادم الرمز فقط | هل يمكن تنبيه تلقائي عند انخفاض الرصيد |
> إن ظهر المفتاح السري في محادثة أو ملف Postman مرفق، فجدّده من لوحة MsgPlus ثم حدّث `MSGPLUS_API_KEY` في Render.

## 2) متغيرات Render الأخرى
| المتغير | القيمة | متى |
|---|---|---|
| `TOTP_ENC_KEY` | `openssl rand -base64 32` | قبل تفعيل 2FA لأي أدمن |
| `REGISTRATION_OTP_ENABLED` | اتركه `false` | `true` فقط بعد نجاح اختبار MsgPlus |
| `ADMIN_2FA_DISABLED` | لا تضبطه | طوارئ فقط (ضياع هاتف الأدمن) |
| `ADMIN_PASSWORD_RESET_TOKEN` + `ADMIN_PASSWORD_RESET_EXPIRES_AT` | رمز عشوائي 32+ حرفاً + تاريخ انتهاء ISO خلال 24 ساعة | لإعادة تعيين كلمة مرور الأدمن مرة واحدة، واحذفهما بعدها |

لا تغيّر `AUTH_SECRET`.

## 3) توافق وسلوك بعد النشر
- الجلسات الحالية تبقى صالحة (التوكن بلا إصدار = 0).
- تُبطَل كل الجلسات القديمة عند: تغيير كلمة المرور/الهاتف، «تسجيل الخروج من كل الأجهزة»، إيقاف/تفعيل الحساب، تفعيل/تعطيل 2FA للأدمن (يبقى الأدمن الحالي مسجّلاً).
- «الخروج من كل الأجهزة» يحذف أيضاً رموز الإشعارات لذلك الحساب.
- كلمات المرور الجديدة 8 أحرف على الأقل؛ القديمة تعمل وتُرقَّى تلقائياً عند أول دخول ناجح.
- **سياسة الإيصال:** إيصال شام كاش مرتبط بطلب لا يُقبل لطلب آخر **حتى لو أُلغي الطلب الأول**. العميل يرفع إيصال تحويل جديداً. (لا يكشف إعادة ترميز لقطة الشاشة — حد معروف.)
- الرفع (الطلبات، الطلبات الخاصة، صور القطع) يُرفض إن تجاوز 6MB قبل قراءة المحتوى (413).
- **حسابات البريد (المسوّق بلا هاتف/كلمة مرور):** يضيف رقمه برمز SMS فقط (بلا كلمة مرور حالية) ويصبح موثّقاً؛ يضيف أول كلمة مرور بلا كلمة حالية (مرة واحدة، ويُرفض لو وُجدت)؛ حساب له هاتف وبلا كلمة مرور يضيف كلمة المرور أولاً قبل تغيير الهاتف. «نسيت كلمة المرور» داخل الحساب ترسل رمز SMS إلى هاتف الحساب وتُبقي الجهاز مسجّلاً (تنتهي الجلسات الأخرى).
- **رابط الإحالة:** لا يُسلَّم للمسوّق (ولا يُنسخ/يُشارك من التطبيق) قبل إضافة رقمه وتأكيده. الكود المكتوب يدوياً عند تسجيل ورشة ما زال يعمل (لم يُغيَّر منطق الإحالة/العمولات).
- **لوحة الإدارة:** صفحة «سعر صرف الليرة» تقرأ `/api/settings` وصارت متاحة للمدير؛ «مستحقة الدفع» = المكتسب − المدفوع − المحجوز بطلبات تحويل (نفس قاعدة لوحة المسوّق).

## 4) التحقق بخطوتين للأدمن (F-03)
1. اضبط `TOTP_ENC_KEY` وانشر. 2. لوحة الإدارة ← «الأمان» ← إعداد، أضف المفتاح لتطبيق مصادقة، أدخل الرمز، **احفظ رموز الاسترداد الثمانية**. 3. لا يُفرض على أي أدمن قبل أن يُنهي إعداده. 4. ضياع الهاتف: رمز استرداد، أو الطوارئ `ADMIN_2FA_DISABLED=true` مؤقتاً.

- كل الـ Actions مثبّتة الآن على commit SHA (بنفس الإصدار الرئيسي السابق v4/v2 لتجنّب تغيّر السلوك). **لم تُشغَّل بعد**: راقب أول تشغيل. (`gh api` غير متاح هنا؛ حُلّت عبر `git ls-remote`.)
- بناء الإصدار يتطلب الآن مفتاح التوقيع: `prepare_android.py --require-release-signing`، و`verify_apk.sh` يفشل لو كان التوقيع debug (للاستثناء المحلي: `EURO_ALLOW_DEBUG_SIGNING=1`).

- `firebase/google-services.json` مرفوع (إعداد عميل Firebase، ليس سراً)؛ قيّد مفتاح API في Google Cloud على حزمة التطبيق.

### خطوات حماية GitHub (تُنفَّذ من إعدادات كل مستودع، لا يمكن من هنا)
> الحالة المقروءة (قراءة فقط): المستودعات الثلاثة **عامة (public)**؛ Secret scanning و Push protection **مفعّلان** مسبقاً؛ Dependabot security updates **معطّل**؛ `main` **غير محمي**؛ لا توجد Rulesets. إعدادات Actions وDependabot alerts لم أستطع قراءتها (محجوبة).
1. **حماية `main`**: Settings → Rules → Rulesets → New branch ruleset، الهدف `main`: فعّل **Block force pushes** و**Restrict deletions** و**Require status checks to pass** (اختر فحوصات البناء: `unit-tests` و`build` في «Next.js build check» و`npm-audit` في «Security audit» لـ al-euro؛ `Build Android release APK` و`validate` لـ euro-car.syria). **لا تفعّل Require a pull request** إن أردت أن أستمر بالرفع مباشرة إلى `main`.
2. **Dependabot**: Settings → Code security → فعّل Dependency graph و**Dependabot alerts** و**Dependabot security updates** (ملف `dependabot.yml` موجود في al-euro؛ أضف مثله للمستودعين الآخرين إن لم يوجد).
3. **Secret scanning**: أبقِ Push protection مفعّلاً. وبما أن المستودعات عامة، لا تضع أي مفتاح أو كلمة سر فيها أبداً (متغيرات Render و Actions secrets فقط).
4. **Actions**: Settings → Actions → General → Workflow permissions = **Read repository contents** (النشر يرفع الصلاحية داخل مهمة `publish` فقط)، وAllowed actions = «GitHub + المحدّدة» (`subosito/flutter-action` مثبّتة على commit SHA).
5. **أسرار الإصدار**: `ANDROID_KEYSTORE*` في Settings → Secrets and variables → Actions فقط، ولا تظهر في السجلات؛ احتفظ بنسخة احتياطية خارج GitHub لملف التوقيع وكلمته (فقدانه يمنع تحديث التطبيق على الأجهزة).
6. **المصادقة**: فعّل 2FA على حساب GitHub نفسه، وراجع Settings → Applications للتطبيقات المخوّلة.
